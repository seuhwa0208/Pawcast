# POWCAST 결제 API 및 배송지 입력 연동 안내

## 1. 문서 목적

POWCAST에서 사용할 결제 API 발급 절차와 배송지 입력을 위한 주소 검색 서비스 적용 방법을 정리한다.

- 배송 추적 API는 사용하지 않는다.
- 배송 상태는 관리자가 POWCAST 관리자 기능에서 직접 변경한다.
- 결제는 토스페이먼츠를 주 PG로 사용해 카드, 계좌 결제 및 간편결제를 통합하는 방식을 권장한다.
- 배송지 검색은 Kakao 우편번호 서비스를 사용한다.

---

## 2. 권장 결제 구성

```text
POWCAST
  └─ 토스페이먼츠 PG
       ├─ 신용카드·체크카드
       ├─ 계좌이체·가상계좌
       ├─ 토스페이
       └─ 카카오페이
```

카드사와 은행마다 API 키를 별도로 발급받는 방식이 아니다. 토스페이먼츠와 전자결제 계약을 맺고, 사용할 결제수단을 계약에 포함하면 PG가 카드사·은행·간편결제 연결을 중계한다.

카카오페이도 토스페이먼츠에서 지원하는 결제수단으로 계약하는 방식을 우선 권장한다. 이렇게 하면 카카오페이 API를 별도로 개발하지 않고 하나의 결제창과 승인 흐름으로 관리할 수 있다.

---

## 3. 토스페이먼츠 API 키 발급 방법

### 3.1 개발용 테스트 키

1. [토스페이먼츠 개발자센터](https://developers.tosspayments.com/)에 가입하고 로그인한다.
2. 개발 연동 체험 상점을 확인하거나 생성한다.
3. 개발자센터의 `API 키` 메뉴로 이동한다.
4. 테스트 환경이 선택되어 있는지 확인한다.
5. 테스트 클라이언트 키와 테스트 시크릿 키를 확인한다.

테스트 키로 진행한 결제는 실제 금액이 출금되지 않는다.

공식 안내: [토스페이먼츠 API 키](https://docs.tosspayments.com/reference/using-api/api-keys)

### 3.2 운영용 라이브 키

1. 토스페이먼츠에서 전자결제를 신청한다.
2. 사업자정보, 판매 상품, 쇼핑몰 URL 및 필요한 서류를 제출한다.
3. 사용할 결제수단을 신청한다.
   - 신용카드·체크카드
   - 계좌이체 또는 가상계좌
   - 토스페이
   - 카카오페이
4. PG 및 카드사 심사를 완료한다.
5. 승인된 상점을 개발자센터에서 선택한다.
6. `API 키` 메뉴의 라이브 환경에서 라이브 클라이언트 키와 라이브 시크릿 키를 확인한다.

라이브 키는 실제 결제가 발생하므로 테스트 환경과 운영 환경을 반드시 분리한다.

### 3.3 키별 사용 위치

| 키 | 사용 위치 | 공개 여부 |
| --- | --- | --- |
| 클라이언트 키 | Vue에서 토스페이먼츠 SDK 및 결제창 초기화 | 브라우저에서 사용 가능 |
| 시크릿 키 | Spring Boot에서 결제 승인·취소·조회 API 호출 | 절대 외부 공개 금지 |

시크릿 키는 다음 위치에 넣으면 안 된다.

- Vue 소스 코드
- `VITE_`로 시작하는 프런트엔드 환경변수
- GitHub 저장소
- 브라우저 번들
- 메신저나 문서의 평문

Spring Boot 서버 환경변수 또는 운영 환경의 시크릿 저장소에만 보관한다.

예시 환경변수명:

```properties
TOSS_PAYMENTS_CLIENT_KEY=test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm
TOSS_PAYMENTS_SECRET_KEY=test_gsk_...
```

현재 전달받은 POWCAST 클라이언트 테스트 키:

```text
test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm
```

이 키는 브라우저에서 테스트 결제창을 초기화할 때만 사용한다. `test_`로 시작하는 테스트 키이므로 실제 결제 운영에는 사용할 수 없다. 운영 전에는 토스페이먼츠 상점 심사 후 발급되는 `live_gck_...` 클라이언트 키로 교체해야 한다.

키 이름에 `docs`가 포함되어 있으므로 토스페이먼츠 문서에서 제공하는 공용 테스트 키 형식이다. 기본 결제 흐름 개발에는 사용할 수 있지만, POWCAST 상점에 계약된 카카오페이 등 개별 결제수단을 테스트할 때는 토스페이먼츠 개발자센터에서 POWCAST 테스트 상점을 선택한 뒤 해당 상점 전용 클라이언트 키를 확인해야 한다.

> 주의: 클라이언트 키는 브라우저에서 사용하는 공개 식별값이지만 시크릿 키는 다르다. `test_gsk_...`, `live_gsk_...` 시크릿 키는 이 문서나 프런트엔드 코드에 절대 기록하지 않는다.

클라이언트 키를 백엔드에서 프런트엔드로 전달할 수도 있지만, 시크릿 키는 어떤 경우에도 프런트엔드로 전달하지 않는다.

## 4. 카카오페이 적용 방법

### 권장: 토스페이먼츠 결제수단으로 계약

POWCAST에서는 카카오페이를 직접 연동하기보다 토스페이먼츠 계약에 카카오페이를 포함하는 방식을 권장한다.

1. 토스페이먼츠 전자결제 신청 과정에서 카카오페이 사용을 신청한다.
2. 계약과 심사를 완료한다.
3. 토스페이먼츠 결제창에 카카오페이를 노출한다.
4. 결제 승인과 결과 처리는 기존 토스페이먼츠 승인 API를 사용한다.

토스페이먼츠 공식 FAQ에 따르면 카카오페이는 계약 후 발급된 테스트 키로 테스트할 수 있다.

참고: [토스페이먼츠 자주 묻는 질문](https://docs.tosspayments.com/resources/faq)

### 선택: 카카오페이 직접 연동

카카오페이를 토스페이먼츠와 별도로 직접 연동해야 하는 특별한 요구가 있을 때만 검토한다.

1. [카카오페이 파트너센터](https://partner.kakaopay.com/)에서 사업자 등록 및 가맹점 신청을 진행한다.
2. 비즈프로필과 계약 절차를 완료한다.
3. 카카오페이 개발자센터에서 계약된 애플리케이션 및 인증정보를 확인한다.
4. 카카오페이 결제 준비·승인·취소 흐름을 별도로 개발한다.

직접 연동하면 토스페이먼츠 결제와 카카오페이 결제의 승인, 취소, 웹훅 및 정산 처리를 따로 관리해야 하므로 현재 POWCAST 범위에는 권장하지 않는다.

공식 안내: [카카오페이 API 및 애플리케이션 유형](https://developers.kakaopay.com/docs/getting-started/basic/api-and-application-type)

## 5. POWCAST 결제 처리 흐름

```text
1. Vue가 Spring Boot에 주문 생성을 요청
   POST /api/orders

2. Spring Boot가 가격과 재고를 검증하고 주문번호 생성

3. Vue가 결제 준비 요청
   POST /api/orders/{orderId}/payments

4. Vue가 토스페이먼츠 클라이언트 키로 결제창 실행

5. 결제 인증 성공 후 Spring Boot가 승인 요청
   POST /api/orders/{orderId}/payments/{paymentId}/confirm

6. Spring Boot가 토스페이먼츠 시크릿 키로 결제 승인

7. 승인된 주문만 결제완료 상태로 변경
```

결제 금액과 주문번호는 반드시 Spring Boot가 DB의 주문 정보와 비교해 검증한다. 프런트엔드가 보낸 금액만 신뢰해서 승인하면 안 된다.

토스페이먼츠 결제 흐름: [결제 흐름 이해하기](https://docs.tosspayments.com/guides/v2/get-started/payment-flow)

## 6. 배송지 입력: Kakao 우편번호 서비스

### API 키 발급 여부

Kakao 우편번호 서비스는 **API 키를 발급받을 필요가 없다.**

- 키 발급 없음
- 사용량 제한 없음
- 상업적 용도 사용 가능
- 우편번호 및 도로명 주소 검색 가능

공식 안내: [Kakao 우편번호 서비스 가이드](https://postcode.map.kakao.com/guide)

### 프런트엔드 적용 방식

Kakao 우편번호 서비스는 일반적인 npm 라이브러리와 다르게 적용한다.

1. `npm install`을 실행하거나 JavaScript 파일을 직접 다운로드할 필요가 없다.
2. 카카오 개발자 사이트에 가입하거나 앱을 생성해 JavaScript 앱 키를 발급받을 필요가 없다.
3. Vue 프로젝트 최상단의 `index.html`에 외부 스크립트 한 줄만 등록한다.
4. 브라우저가 페이지를 열 때 Kakao 서버에서 우편번호 검색 기능을 불러온다.
5. 로딩 후 Vue 컴포넌트에서 `new window.kakao.Postcode(...)`로 주소 검색 팝업을 실행한다.

즉, Kakao가 외부에 제공하는 무료 주소 검색 스크립트를 POWCAST의 HTML에 연결해서 사용하는 구조다.

`D:\POWCAST\frontend\index.html`의 `<body>` 안에 다음 스크립트를 등록한다.

```html
<script src="//t1.kakaocdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js"></script>
```

현재 POWCAST 프로젝트의 `index.html`에도 위 스크립트가 적용되어 있다. 한 번 전역으로 불러오므로 각 Vue 컴포넌트에서 같은 `<script>` 태그를 반복해서 추가하지 않는다.

주소 검색 버튼을 누르면 우편번호 검색창을 열고, 선택된 값을 Vue 입력 데이터에 반영한다.

```javascript
new window.kakao.Postcode({
  oncomplete(data) {
    addressForm.zipcode = data.zonecode;
    addressForm.address1 = data.roadAddress || data.jibunAddress;
  },
}).open();
```

사용자는 상세주소를 직접 입력한다.

```text
zipcode  ← data.zonecode
address1 ← data.roadAddress 또는 data.jibunAddress
address2 ← 사용자 직접 입력
```

### POWCAST 배송지 API 연결

Kakao 우편번호 서비스는 주소를 검색하는 기능만 제공한다. 선택한 배송지를 저장하고 관리하는 것은 POWCAST Spring Boot API가 담당한다.

| 기능 | Method | POWCAST API |
| --- | --- | --- |
| 배송지 목록 | GET | `/api/members/me/addresses` |
| 배송지 등록 | POST | `/api/members/me/addresses` |
| 배송지 수정 | PATCH | `/api/members/me/addresses/{addressId}` |
| 배송지 삭제 | DELETE | `/api/members/me/addresses/{addressId}` |

배송지 등록 예시:

```json
{
  "label": "우리 집",
  "recipient": "이수미",
  "tel": "010-1234-5678",
  "zipcode": "21390",
  "address1": "인천광역시 부평구 경원대로 1366",
  "address2": "101동 1203호",
  "isDefault": true
}
```

## 7. 배송 상태 처리 방침

POWCAST에서는 외부 배송 추적 API를 사용하지 않는다.

- 관리자가 관리자 주문 화면에서 배송 상태를 변경한다.
- 택배사 실시간 위치 및 운송장 자동 추적은 구현하지 않는다.
- 회원 화면은 서버의 주문 상태를 조회해 표시한다.

권장 상태 흐름:

```text
결제완료 → 상품준비중 → 배송중 → 배송완료 → 구매확정
```

관리자 상태 변경 API는 기존 명세의 다음 기능을 사용한다.

- `PATCH /api/admin/orders/{orderId}/status`
- 필요한 경우 관리자 배송완료 처리 API 추가 또는 기존 상태 변경 API의 허용 상태 확장

상태 변경 권한과 허용 가능한 상태 전이는 반드시 백엔드에서 검증한다.

## 9. 비회원 결제 완료 이메일

기능정의서 v4의 `FN-GST-01`에 따라 비회원 주문 시 주문자 이름, 이메일, 전화번호와 배송지를 입력받는다. 결제가 최종 승인되면 주문번호와 주문내역을 입력한 주문 이메일로 발송한다.

권장 처리 흐름:

```text
1. Vue 주문서에서 비회원 주문자 이름·이메일·전화번호 입력
2. POST /api/orders 요청에 주문 이메일 포함
3. Spring Boot가 주문번호를 생성하고 주문 정보 저장
4. 토스페이먼츠 결제 인증 후 서버 승인 수행
5. 주문번호·금액·승인 결과와 중복 처리 여부 검증
6. PAYMENTS와 ORDERS를 결제완료로 반영
7. 트랜잭션 완료 후 이메일 발송 작업 등록
8. 주문번호와 주문 상품·금액·배송지 요약을 이메일로 발송
```

이메일 발송은 Vue나 토스페이먼츠가 직접 처리하지 않는다. Spring Boot가 PG 승인과 DB 반영이 모두 성공한 뒤 메일 서비스로 발송해야 한다.

이메일에 포함할 권장 항목:

- POWCAST 주문번호 (`ORD-yyyyMMdd-6자리 난수`)
- 주문 일시
- 주문 상품명·옵션·수량·주문 당시 가격
- 상품 금액·배송비·최종 결제 금액
- 수령인과 배송지 요약
- 결제수단
- 비회원 주문 조회 안내

비회원 주문 조회 시에는 기능정의서에 따라 `주문번호 + 주문 이메일`을 함께 검증한다. 이메일 주소만으로 주문 정보를 조회할 수 있게 구현하면 안 된다.

메일 발송 실패가 결제 승인 자체를 되돌리게 해서는 안 된다. 결제와 주문 저장 후 이메일 작업을 별도 큐 또는 재시도 가능한 발송 상태로 관리하는 방식을 권장한다.
